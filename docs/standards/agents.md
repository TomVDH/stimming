# Agent standards

How any agent (Claude, Gemini, Codex, Cursor) works in Stimming. Terms follow `GLOSSARY.md`.

## Instruction files

| File | Holds | Who writes it |
|---|---|---|
| `ADJUDANT.md` | Operating rules: voice, vault writes, beans, git | Generated by adjudant. Never edit. |
| `AGENTS.md` | Project index and the hard rules. Under 100 lines. | Any agent, from Tom's words |
| `CLAUDE.md`, `GEMINI.md` | Tool-only overrides. They import the two files above. | Any agent, tool-only rules |
| `docs/standards/*.md` | The full standards: agents, code, process | Any agent, from Tom's words |
| `DESIGN.md`, `PRODUCT.md` | Look and product truth, in the impeccable format | Any agent, from Tom's words |
| `GLOSSARY.md` | Project terms. No implementation detail. | Any agent, when a term settles |
| `docs/menu.md` | The menu as it is now | Any agent, same commit as the code |
| `docs/toys/<id>.md` | One toy as it is now, with its Rules and Direction | Any agent, same commit as the code |
| `<dir>/AGENTS.md` | Rules for one folder that differ from the root | Any agent, from Tom's words |

- Nested `AGENTS.md` files: `shared/`, `icons/`, and the workbenches `barlab/`, `fxlab/`, `introlab/`, `glasslab/`, `menulab/`, `serieslab/`. A nested file never repeats the root.
- Before work on a toy, read its `docs/toys/<id>.md` when one exists.
- Before work on the menu, read `docs/menu.md`.
- `.claude/rules/*.md` load by path in Claude Code. `adjudant-code.md` holds the comment register.

## Rules and history

- A standard changes only from Tom's own words in chat. Never invent one.
- Docs state the rule as it stands: no dates, quotes or rejected options.
- The story of a decision (date, Tom's words, what lost) goes to the vault through adjudant: [[stimming/decisions]]. Docs link to it.
- Shipped code wins over a doc on a fact. Fix the doc.

## Memory

- Claude's memory keeps only Claude-specific habits and pointers.
- A rule about the project goes into the repo docs, so every agent reads it.

## Skills

Use a skill where the project requires one. Other skills are the agent's choice.

| Job | Skill |
|---|---|
| Any write into the vault (decisions, session logs) | `adjudant` |
| Work items | `beans` CLI (`beans prime`) |
| A new feature, toy or look, before code | `superpowers:brainstorming` |
| A bug or a test failure | `superpowers:systematic-debugging` |
| UI and design work; `DESIGN.md`, `PRODUCT.md` | `impeccable` |
| GSAP motion (menu icons) | `gsap-core`, `gsap-timeline` |
| A new hook for a checkable rule | `hookify:writing-rules` |
| A PR before merge | `/code-review` |
| A term or a glossary change | `domain-modeling` |
| A long interview on a plan or standard | `grill-with-docs` |

## Outside Claude Code

Some pieces run only in Claude Code. Another agent reads the same files by hand.

| Piece | In Claude Code | Any other agent |
|---|---|---|
| `ADJUDANT.md` | `@`-imported every turn | Read it first; `AGENTS.md` says so |
| `.claude/rules/adjudant-code.md` | Loads when a code file is read or edited | Read it before editing code |
| Hookify hooks (`.claude/hookify.*.md`) | Fire on matching actions | Read them; follow the rule without the hook |
| Vault writes | Through the `adjudant` skill | Leave the note in the bean; a Claude session writes the vault |
| Plugin skills (`superpowers:*`, `hookify:*`, `/code-review`, `grill-with-docs`) | Invoked by name | Do the same step in plain chat: brainstorm before a feature, debug systematically, review before merge |

## Working in a shared checkout

Toy chats share one checkout. Rules for git and commits: `docs/standards/process.md`.

- Touch only your bean's files. A change in `shared/` needs its own bean and Tom's yes.
- Never iterate icons across toys. Tom starts one chat per toy for icons.
- Open items wait until Tom asks: icons per toy, the content zone per toy, stage tints, the Glass and Coil first-tap stall, Lab moves.
